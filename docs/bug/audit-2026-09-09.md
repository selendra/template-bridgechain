## HIGH

### H-1 — `setLocalToken` on a fresh `debridgeId` is instant; the 48 h governance timelock does not stop an owner drain
`contracts/src/Gate.sol:519-525`. The write-once guard blocks *re-pointing* an
existing corridor, not registering a new one. Owner mints a worthless ERC-20 `W`
on chain A, calls `send(W, 1_000_000e6, B, …)`; validators attest the fact
(their allowlist is opt-in and empty by default, `crates/bridge-core/src/allow.rs:9-14`);
owner calls `setLocalToken(keccak(A,W), USDC_B)` on B with no schedule, then
`claim`. The USDC pot leaves in one block. This is exactly what the
`GOVERNANCE_DELAY` comment (`Gate.sol:183-198`) says the delay exists to prevent.
PoC passed. **Fix:** `_consumeGovernance(keccak("setLocalToken", debridgeId, localToken))`
for first registration too. CONFIRMED.

### H-2 — Solana gate governance has no timelock at all
`crates/solana-gate/src/lib.rs:1546-1590`. `set_validator(active=true)` and a
threshold *lower* are instant; the program upgrade authority is instant; the
same key is the only one that can `init`. A compromised owner key adds one
attacker validator and sets threshold 1 in one block and drains every vault.
On EVM the same key sits 48 h in public view. Both legs share a validator set,
so the EVM timelock is only as strong as the Solana owner key. **Fix:**
owner + upgrade authority behind a Squads/SPL-Governance timelock, or an
on-chain schedule/consume mirroring `_consumeGovernance`. CONFIRMED.

### H-3 — EVM→Solana transfer with `amount ≥ 2^64` is neither claimable nor cancellable: locked forever
`Gate.send` (`contracts/src/Gate.sol:568-593`) has no width cap for a 32-byte
receiver. `ClaimArgs.amount` / `CancelArgs.amount` are `u64`
(`crates/solana-gate/src/lib.rs:169`), `process_cancel` recomputes the id from
the `u64` (`:1005-1015`), and the relayer fails `parse::<u64>()` for both claim
and cancel (`crates/solana-relayer/src/target.rs:283,381`). No cancel marker ⇒
no refund attestation ⇒ no EVM refund. For an 18-decimal token that is
**18.44 tokens**. The in-code claim at `lib.rs:799-828` that such a transfer
"routes into cancel → refund" is false. No decimals normalisation exists
anywhere (Gate, frontend, relayer). Found independently by two reviewers.
**Fix:** `if (receiver.length == 32 && amount > type(uint64).max) revert` in
`send`, plus the same check in the UI. CONFIRMED by code path.

### H-4 — Live Alchemy API key committed and pushed; also served to every browser
- `docker/testnet-mesh5/docker-compose.yml:132-150` (generated by
  `scripts/bridge-from-json.sh:541-556`) inlines the full keyed RPC URL as CLI
  args. The file is tracked and in `origin/master` (`1bdca61`, `44cbaaf`,
  `c9a027e`). `.gitignore` covers `docker/*/configs|.env|keys` but not
  `docker/*/docker-compose.yml`.
- Both launchers put the same private URL into the chain registry
  (`scripts/run.sh:595`, `scripts/bridge-from-json.sh:414`), which
  `crates/graphql-api/src/schema.rs:546-548` returns to any anonymous client and
  the frontend reads (`frontend/src/components/useChainDecimals.ts:27`).
  `docs/operations.md:450` and `graphql-api/src/main.rs:234` say never to do this.

Every validator, keeper, indexer and API on the testnet shares that one key, so
quota exhaustion stops signing across the board. **Fix:** rotate the key now;
treat it as burned; gitignore the generated compose or emit `${VAR}`
references; add a separate public-RPC field to the registry. CONFIRMED.

## MEDIUM

### M-1 — A Relay-scoped token can permanently hide any transfer from both claim and refund
`crates/sig-store/src/main.rs:357-363` → `crates/bridge-db/src/lib.rs:629-697`
(`mark_claimed`): unconditional `SET status='claimed'`, clears an `eligible`
refund_status, no on-chain check, and *parks* a marker for ids with no row yet.
`pending_claims` (`lib.rs:1007`), `sweep_refund_eligible` (`:949`) and
`refund_candidates` (`:965`) all filter `status <> 'claimed'`; nothing ever
writes status back. Because ids are deterministic, a leaked
`SIG_STORE_KEEPER_TOKEN` can pre-poison *future* transfers. "The indexer is the
only writer of refund_status" (`crates/indexer/src/config.rs:45`) is therefore
false. **Fix:** drop the Relay `claimed` route (as was done for
cancelled/refunded) or make the keeper's write advisory in a column the queues
ignore; refuse to park for unknown ids from HTTP. CONFIRMED.

### M-2 — Unbounded signatures per POST = keeper liveness DoS from one validator credential
`crates/sig-store/src/main.rs:285-305`: one POST carries ~1,200 sigs (256 KiB
body); the limiter counts requests. `upsert_signature` reloads all rows per
insert (`bridge-db/src/lib.rs:483-486`, O(n²)); `pending_claims` ships all rows
every tick; the keeper does one `isValidator` eth_call per unknown signer and
drops its memo every 60 s (`crates/keeper/src/main.rs:684-740`). All validators
share one token (`docker-compose.yml:106,121,136`). Previously listed as open
griefing; it is a liveness break. **Fix:** cap sigs per POST (honest client
sends 1, `remote.rs:71`), cap rows per submission, drop non-member signers at
the store. CONFIRMED.

### M-3 — `send` accepts any `chainIdTo`; funds sent to a chain with no gate are locked with no recovery
`Gate.sol:568-593`, no destination registry, no owner sweep. Refund requires a
`Cancelled` on the destination, and the validator skips candidates whose
`chain_id_to` has no reader (`crates/validator/src/refund.rs:337-338`). PoC
passed. **Fix:** `supportedChain[chainIdTo]` check in `send`. CONFIRMED.

### M-4 — No path refunds a stuck Solana→EVM transfer
`crates/validator/src/refund.rs:330` returns unless `source_readers` has
`chain_id_from` (never Solana); the Solana attester handles only
`chain_id_to == Solana` (`crates/solana-relayer/src/refund.rs:159`); nothing
builds `GateInstruction::Refund` (no wire struct, no `gate-admin` subcommand).
`process_refund` is live on-chain but unreachable. CONFIRMED.

### M-5 — `create_account` PDAs can be bricked by a 1-lamport pre-fund (H-2 fix not ported)
- gate `register_asset` (`crates/solana-gate/src/lib.rs:1687-1697`) and `init`
  (`:1197-1201`) — PoC via `solana-program-test`: `account … already in use`.
  `debridge_id` is public in advance; an attacker pre-funds every plausible
  asset PDA and the program must be redeployed.
- swap `create_pda` (`crates/solana-swap/src/lib.rs:309-331`, used at
  `:373,:401,:450`) — same for `["token", mint]` and `["pool"]`.
**Fix:** the `transfer + allocate + assign` sequence `create_marker` already uses. CONFIRMED.

### M-6 — Solana swap pool is weaker than the Solidity pool it mirrors
- First `SetPrice` after listing skips the deviation cap: cooldown *and* cap sit
  under `if rec.last_price_update != 0` (`crates/solana-swap/src/lib.rs:490-500`);
  Solidity exempts only the cooldown (`SwapPool.sol:348-358`). A compromised
  oracle key prices a new token at ~0 and swaps the reserve out in one step.
- No `maxPriceAge` equivalent (`SwapPool.sol:79-92` calls it a security property).
- Fee cap 99.99 % vs 10 %; negative `min_price_update_interval` accepted;
  no `max_price_deviation_bps` setter (`:360,:762,:74,:487`).
CONFIRMED.

### M-7 — Router fallback-to-stable is cheap to force (residual of the FALLBACK_GRACE fix)
`contracts/src/SwapRouter.sol:127,430-446,484-497`. `deferredSince` is started
by anyone; `_swapBlocked` needs `out > reserve` only at the instants `finalize`
is evaluated; `pool.swap` is permissionless and fee-free by default. Attacker
sandwiches each `finalize` (swap out → finalize → swap back) in one tx, then
after 6 h drains, finalizes to `FinalizeFallback`, restores. User's signed
`finalToken`/`finalMinOut` is bypassed for gas cost; capital is held per block,
not 6 h. Asset downgrade, not loss. CONFIRMED.

### M-8 — GraphQL: unbounded lists with per-row `eth_call` fan-out
`crates/graphql-api/src/schema.rs:500,673,722` load the whole `submissions`,
`signatures` and `swap_bridges` tables (`bridge-db/src/lib.rs:517-521,751-800`);
`executed`/`cancelled`/`status` are one uncached `eth_call` each
(`schema.rs:270-299`, `chain.rs:155-171`). `limit_complexity(1000)` has no list
multiplier. `{ submissions { status executed cancelled } }` costs 4·N eth_calls
against the operator's RPC per request, forever growing. **Fix:** SQL
pagination, `complexity = count * child_complexity`, memoise terminal flags. CONFIRMED.

### M-9 — HTTP client to the *untrusted* store has no timeout and no body-size bound
`crates/bridge-core/src/remote.rs:58-61`. Validator calls `fetch_allowlist`
before every batch and `upsert` per event; a store that accepts and never
answers hangs every scan loop; a multi-GB body OOMs validator and keeper. CONFIRMED.

### M-10 — Postgres published on all interfaces with `bridge:bridge`
`scripts/run.sh:442-445` (`-p ${PG_PORT}:5432`, bypasses ufw);
`scripts/bridge-from-json.sh:646-651` with `config/bridge.config.json:20` =
`"bridge"`. The live testnet used the same. Signatures, `pending_lifecycle`,
allowlists and cursors are writable by anyone who can reach the port.
**Fix:** `127.0.0.1:` bind + random password (the compose path does both). CONFIRMED.

### M-11 — `bridge-from-json.sh` writes private-key TOMLs 0644 before `umask 077`
The umask at `scripts/bridge-from-json.sh:672` comes after every service config
is generated; empirically `~/.local/state/bridge-mesh5/*.toml` are `-rw-r--r--`
and contain `private_key`. Default `run_dir` is `/tmp/bridge-json-run`. CONFIRMED.

### M-12 — Production safety is opt-in by a string, and never reaches the Solana gate
`scripts/deploy-from-json.sh:60-91`: all checks live under `PROFILE == "production"`;
the `local` path (`:171-213`) deploys threshold 1 / owner = deployer hot key /
no guardian on *any* chain id without refusing (`config/testnet5.deploy.local.json:4`
shows Gen-5 was deployed `local`). For Solana (`:494-505`) even `production`
leaves owner = deploy payer keypair and guardian optional. CONFIRMED.

### M-13 — Solana refund attester trusts the store's timeout instead of establishing it on-chain
`crates/solana-relayer/src/refund.rs:157-178` acts on `refund_candidates()`;
the EVM loop deliberately re-derives the age on-chain (`validator/src/refund.rs:338-349`, H-2).
Anyone who can flip `refund_status` gets validators to cancel a fresh,
deliverable transfer (censorship, not double-spend). CONFIRMED.

## LOW

- **Matured schedules never expire.** `Gate.sol:353-358,428-432`. A schedule is a
  banked instant right for life; a stolen owner key inherits every matured one.
  PoC executed an add 3 years after scheduling. Add a grace window.
- **Keeper trusts the store's `signer` label.** `crates/keeper/src/main.rs:717-741,779-802`
  never recovers the address; duplicate/junk rows labelled with a member address
  make every claim revert at estimateGas forever. Recover + dedupe by recovered address.
- **Receipt timeout + pending nonce = queued duplicate txs.** `main.rs:43,535-556`.
  A stuck tx times out, `executed()` is still false, a duplicate is queued at
  nonce+1 every tick; all revert `AlreadyExecuted` and pay gas once the first
  mines. Track pending hash or fee-bump. PLAUSIBLE.
- **Refund loop swallows store errors.** `main.rs:233,361` `unwrap_or_default()`;
  a 401/500 means refunds silently never happen.
- **`park_if_missing` TOCTOU** loses a `Claimed` in a ms window during concurrent
  backfill (`bridge-db/src/lib.rs:629-697` vs `:813-822`); `record_finalized`
  has no park path at all (`:917-936`). History-only.
- **Relayer ignores `auto_params`** (`solana-relayer/src/target.rs:289,380`): an
  EVM→Solana send with autoParams fails `NotEnoughSignatures` every poll, burning fees.
- **`refund.timeout_secs` unvalidated** (`validator/src/config.rs:60`): 0 or
  negative disables the H-2 age gate silently.
- **Keyed RPC URLs logged** (`validator/src/main.rs:189`, `provider.rs:53-108`).
- **Corrupt/zero-length state file clears a persisted pause** (`validator/src/state.rs:93-139`,
  rename without fsync). PLAUSIBLE.
- **Failover can advance the cursor past unscanned blocks**: `latest` from one
  endpoint, `get_logs` from a lagging one (`main.rs:220-233,338`). PLAUSIBLE.
- **Allowlist (the kill-switch) is served by the untrusted store** (`allow.rs:19-21`);
  no independent second source.
- **Router `rescue` can sweep claimed-but-unfinalized stable** (`SwapRouter.sol:369-400`);
  later finalizes pay from other transfers' balance.
- **Frontend EVM→Solana send cannot be encoded**: base58 receiver passed
  straight to a hex encoder (`BridgeView.tsx:409-419`, `wallet/eth.ts:49-54`);
  fails closed with "bad bytes". No e2e covers the direction.
- **`COPY . .` bakes secrets into the builder layer** (`Dockerfile:11`,
  `docker/Dockerfile.relayer:9`); `.dockerignore` misses `docker/*/configs|.env|keys`,
  `.solana/`, `*.config.local`, `config/deployments/`.
- **Secrets on command lines / stdout**: keyed RPC in `graphql-api` argv
  (`run.sh:602,618`, `bridge-from-json.sh:728,762`); `run.sh:652` prints `DEPLOYER_KEY`.
- **CI**: no `permissions:` block, actions pinned by tag not SHA, SBF
  `deploy-readiness` is `continue-on-error` (`ci.yml:224`) although the program
  is live; `Dockerfile.frontend:10` uses `npm install` without the lockfile CI tests.
- **`stop.sh` pkills by loose pattern** (`vite`, `anvil --chain-id`).
- **Solana `init`** accepts duplicate/zero validators and any `chain_id`
  (`solana-gate/src/lib.rs:1175-1183`); an EVM chain id here would be the one
  cross-leg replay path (operator error).
- **Validator `/status` unauthenticated**, no rate limit on bearer compare (`validator/src/api.rs:65-67`).
- **Stale docs**: `operations.md:329,341-342,357` and `bridge-from-json.sh:667`
  describe an unauthenticated store / no deploy script; both are wrong now.

## Fixes applied 2026-09-09 — SwapRouter

`contracts/src/SwapRouter.sol` only (not upgradeable; a redeploy per chain plus
`setRemoteRouter` re-wiring). `SwapPool.sol`, `Gate.sol`, the `finalize` /
`claimAndFinalize` / `swapAndBridge` signatures and every event the indexer decodes
(`Finalized`, `FinalizeFallback`, `FinalizeDeferred`) are unchanged.

- **M-7** — the stable fallback is now gated by CALLER as well as by time.
  `_settle` computes `mayFallBack = msg.sender is finalReceiver || owner ||
  guardian` and passes it into `_deliver`. When the swap is blocked
  (`_swapBlocked`, evaluated at that instant) the new `_deferOrFallBack` starts
  the `deferredSince` clock if unset and then delivers the stable only if
  `block.timestamp >= since + FALLBACK_GRACE` AND `mayFallBack`; otherwise it
  emits `FinalizeDeferred` (with a `retryAfter` that may already be in the past)
  and returns without settling. The `catch` branch of the real `pool.swap`
  attempt used to settle to the stable on the spot; it now goes through the
  same `_deferOrFallBack`, so there is no second unguarded route to the
  fallback. `MIN_DELIVER_GAS` and the 63/64 reasoning are unchanged; a starved
  call still reverts `InsufficientGas` before the attempt.
  New: `address public guardian`, `setGuardian` (onlyOwner, `GuardianSet`).
  The guardian can only release a blocked transfer's stable to its OWN signed
  receiver after the window (same right as the receiver) and cancel a stable
  rescue; it can never redirect funds.
  Honest guarantee (docblock at `FALLBACK_GRACE`): a third party — keeper or
  attacker — can never convert a transfer to the stable, whatever the clock
  says; the sandwich now buys nothing but a `FinalizeDeferred` log. A receiver
  (or owner/guardian) who calls `finalize` after the window is opting in to
  the stable IF the swap is blocked at that instant, and a public-mempool call
  can still be sandwiched into that state — a receiver who wants the token
  should leave the retries to the keeper or use a private relay. Funds never
  strand: the owner can always release to the signed receiver after the window.
- **LOW (rescue sweeps claimed-but-unfinalized stable)** — `owedStable` only
  knows about transfers `finalize` has seen and deferred; a plain `Gate.claim`
  into the router is invisible and the router cannot enumerate the Gate's
  claims. So `rescue(stable, ..)` now reverts `StableRescueRequiresSchedule()`
  unconditionally (every other token still sweeps instantly). The stable goes
  through `scheduleStableRescue(amount, to)` (onlyOwner, emits
  `StableRescueScheduled(amount, to, readyAt)`, re-scheduling replaces and
  restarts), `cancelStableRescue()` (owner or guardian), and
  `executeStableRescue()` (onlyOwner) which is valid only in
  `[readyAt, readyAt + STABLE_RESCUE_WINDOW]` (`STABLE_RESCUE_DELAY = 48 hours`,
  `STABLE_RESCUE_WINDOW = 7 days`; errors `StableRescueNotScheduled`,
  `StableRescueNotReady(readyAt)`, `StableRescueExpired(readyAt)`) and pays at
  most `balance - owedStable` at execution time (`RescueWouldTakeOwedFunds`).
  The 48 h public window is what closes the gap: every claimed-but-unobserved
  transfer gets finalized (leaves the balance) or deferred (lands in
  `owedStable`) by the keeper's routine retries before `free` is computed.
  Residual, documented on `scheduleStableRescue`: a transfer claimed in the
  final moments before execution is protected only by the owner checking the
  indexer for `Claimed`-without-`Finalized`; schedule the amount identified as
  stranded, not the whole balance.

Tests (`contracts/test/SwapRouter.t.sol`, 17 -> 29): `test_M7_*` (7) — third party

party too; receiver bound by the window; owner and guardian can release (to the
